## Start with a known project

Run `npm test` in the [Task API lab](/books/hands-on-coding-assistants/lab.tar.gz) and check `opencode --version`. These examples use the OpenCode 2 CLI. The lab already includes `opencode.jsonc` with permission rules. It leaves model selection to you.

## Choose between a local and a hosted model

When OpenCode reads `src/app.ts` to answer a question, the text it reads becomes part of the model's context. The model processes that context to generate an answer. Where that processing happens is the difference between the two paths in this chapter.

- **Local.** Ollama runs a downloaded model on your machine. Model requests stay on that machine. You need disk space for the download and enough memory to run the model with the context your task needs.
- **Hosted.** A provider runs the model on its servers. OpenCode sends the prompt and relevant context over the network, which can include code excerpts and tool output. The provider supplies the computing power, and its terms govern usage and data retention. A free option may have quotas or limited availability.

Use Ollama if you want model requests to stay on your machine and the model fits your hardware. Try a free hosted model if the download or memory requirements get in the way. Both paths use the same lab. Whichever you pick, check that the model can read a file and run a test through OpenCode.

## Run a local model with Ollama

Before downloading a model, [check whether it fits your machine](/books/hands-on-coding-assistants/appendices/model-setup/#check-whether-a-model-fits-your-machine). Use the exact model variant and leave room for the context OpenCode will send.

Install Ollama for your operating system. Start its app or run `ollama serve` if your installation uses the command line. In a second terminal, download a local model:

```sh
ollama pull qwen3.5:9b
ollama list
```

Start `opencode` from the lab and open `/models`. OpenCode 2 discovers completion models on the default Ollama listener at `127.0.0.1:11434`. Select `ollama/qwen3.5:9b`. The [model setup appendix](/books/hands-on-coding-assistants/appendices/model-setup/) covers context, missing models, and non-default ports.

Ollama also documents `ollama launch opencode` as an entry point. Confirm the selected local tag in either workflow. Expect memory and speed to vary with the model, quantization, context length, and hardware.

## Run a free hosted model

Open `/models` and look for a current free entry in the OpenCode catalog. Select its explicit model ID so you can record what the experiment used. If the entry is unavailable, the appendix gives another provider option. Free offerings can change or enforce usage limits. Work with the sample project and its fictional data when sending context to a remote service.

You can also list models from the terminal:

```sh
opencode models
```

## Check file and shell tools

In the lab folder, run `opencode`, select **Build** and ask OpenCode to do a read-only check:

```text
Read package.json. Report the test script exactly as written, then run
npm test and report the observed exit status. Leave all files unchanged.
```

Open the tool output. Confirm that the assistant actually read `package.json` and ran the test command. Run `git status --short` yourself. It should be empty if you committed the starter and changed no config. If the model describes the steps but skips a tool, switch to another model before moving on.

## Read the permission prompts

The starter allows the exact test commands and asks about other shell commands. Use the prompt to inspect the command and its working directory. You can approve one command to try it or revise the plan if it would do more than the spec calls for. The [automation chapter](/books/hands-on-coding-assistants/chapters/hooks-validation-and-agent-automation/) shows where to put a check you want to run every time.

Once the model can read a file and run a check, [use it to explore the application](/books/hands-on-coding-assistants/chapters/exploring-an-unfamiliar-codebase/).
