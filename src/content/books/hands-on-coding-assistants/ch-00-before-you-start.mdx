## Who this book is for

You already write software. You can open a terminal, read a diff, and run a test suite. You'll use those skills in every chapter. The work starts with a task you can explain and ends with a change you can defend.

The exercises use OpenCode, an open-source coding harness that runs in your terminal—_Don't worry if you're not familiar with harness or any other specific term used here. We'll define them as we go_. Bring the editor you already use. You can run a model on your machine with Ollama or choose a free hosted model. Either way, you'll work against the same spec and check the result with the same tests.

## What to install

- **Git** to record the starter state and review changes with `git diff`.
- **Node.js 24 or later** and npm to run the TypeScript lab and its tests. The lab uses the Node.js standard library and requires no application package install.
- **OpenCode 2.x** to follow the terminal examples.
- **Ollama** if you want local inference. Follow [the setup chapter](/books/hands-on-coding-assistants/chapters/setup-and-practical-integration/) for the model setup.

The shell examples use POSIX syntax. On Windows, use Git Bash for those commands or adapt them to PowerShell.

Check the local commands before opening the agent:

```sh
git --version
node --version
npm --version
opencode --version
```

## Get the lab

[Download the Task API starter](/books/hands-on-coding-assistants/lab.tar.gz), extract it to a fresh directory, and open a terminal in the directory containing `package.json`. You can use your archive tool or extract it with `tar`:

```sh
mkdir task-api-lab
tar -xzf lab.tar.gz -C task-api-lab
cd task-api-lab
git init
git add .
git commit -m "Start the Task API lab"
npm test
```

If Git asks for an author, set `user.name` and `user.email` in this repository and retry the commit. Three starter tests should pass. The archive also includes acceptance tests for two features you'll implement later. Those tests have separate commands so the starter remains green.

## What you need to know

The lab is a small HTTP service. It stores tasks and fictional registrations in memory and listens on the loopback interface. You can run it with `npm start`. Open `http://127.0.0.1:3000/health` to see `{"status":"ok"}`, then stop the server with Ctrl+C. The tests start their own server and use a free port.

You can do the exercises in separate Git branches off your starter commit. The registration exercise and the final task-label exercise are independent. If a model goes in the wrong direction, you can inspect the changes and start again from a known state.

Keep the [model setup appendix](/books/hands-on-coding-assistants/appendices/model-setup/) handy. It records the model choices separately from the exercises, so a provider change leaves the rest of the workflow usable.
