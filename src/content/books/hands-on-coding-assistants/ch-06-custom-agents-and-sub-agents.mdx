## Give the reviewer a different job

The Build agent has already made choices about the implementation. A reviewer can work from the spec and the diff and look for behavior that those choices missed. Give it a narrow question, limited tools, and an answer you can check.

Create `.opencode/agents/reviewer.md` inside the lab. OpenCode 2 loads Markdown agent definitions from that directory. Use `mode: all` so you can select the reviewer directly or call it from another agent. A subagent without a model in its definition inherits the parent session's selection.

```md title=".opencode/agents/reviewer.md"
---
description: Reviews the Task API diff against the feature spec and tests
mode: all
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
  - action: shell
    resource: git diff
    effect: allow
  - action: subagent
    resource: "*"
    effect: deny
---

Read the named spec, the affected code, and the relevant acceptance test.
Use git diff for unstaged changes. Report each finding with its file and
line, an input that demonstrates the problem, and the expected result.
State which checks you relied on. Leave the files unchanged.
```

## Run an independent pass

With the registration diff still unstaged, start a fresh session. Select **reviewer**, or pass the ID at the command line:

```sh
opencode run --agent reviewer "Review the unstaged diff against specs/registration-validation.md."
```

Select a suitable model in OpenCode or add `--model provider/model` using the ID from [the setup chapter](/books/hands-on-coding-assistants/chapters/setup-and-practical-integration/). Verify that the reviewer read the acceptance test and the diff. The reviewer has permission to read the changes. You'll run any commands needed to reproduce its findings.

A second option is to ask **Build** to launch the `reviewer` subagent with the same spec and diff. Watch for a separate child session. In OpenCode 2, subagents run in their own context and report back to the parent. Their permissions come from their own definitions. Review those permissions as you would the main agent's.

## Decide if delegation helps

On a single-route exercise, a fresh reviewer session may be enough. Try splitting the work when two questions have clean boundaries. One reviewer can check response compatibility while you check the mutation order and tests. Compare the findings with what you'd find from a normal diff review. A second agent earns its place when it uncovers something you can reproduce.
