## Give the agent a tool with a narrow job

MCP, the Model Context Protocol, lets a client discover tools supplied by a server and call them with structured input. The lab includes `tools/project-context.mjs`, a small local stdio server. It exposes one tool that returns the Task API's validation conventions. Its result is fixed. It needs no network service or API key.

Run the server's protocol test before asking the model to use it:

```sh
npm run test:mcp
```

The test starts the server, checks the initialization exchange, lists its tool, and calls it. If this fails, fix the process or protocol before changing the prompt.

## Connect the server in OpenCode

Add this top-level `mcp` section to the lab's existing `opencode.jsonc`. Keep its `permissions` field. The example turns off Code Mode so you can see the individual tool call.

```jsonc
{
  "mcp": {
    "servers": {
      "project_context": {
        "type": "local",
        "command": ["node", "tools/project-context.mjs"],
        "codemode": false
      }
    }
  }
}
```

Start a new session from the lab directory, or use:

```sh
opencode mcp list
```

Look for `project_context` with a connected status. A successful connection means the harness started and initialized the server. The next check is whether the selected model calls the tool.

OpenCode 2.3.2 can report an empty registry on the first request in a new directory. If you see `No MCP servers configured`, confirm you're in the lab, run `npm run test:mcp`, and retry `opencode mcp list` with the normal background service. Its `--standalone` list command has a separate discovery issue.

## Ask the model to call it

In **Plan**, send:

```text
Call project_context_get_task_conventions. Report its response and explain
which test in test/app.test.ts checks the state-change convention.
```

Look for the tool call in the session. Its response should describe the 400 status and the unchanged task list. If the model repeats the convention without calling the tool, you have verified that it can answer the question. Ask again or change models to verify the integration. Match the tool name to the one shown by OpenCode.

## Decide what the connection is worth

A server is useful when the information lives outside the files the agent already reads or when it needs a controlled lookup. In this exercise the server makes the protocol observable. In a real repo, use the simplest source that keeps the information current. Each tool you expose has a description the model has to consider and permissions you have to maintain.
