## Make the procedure reusable

The `/check-spec` command starts a prompt at your request. A skill carries a procedure the agent can load when it recognizes a task. Use a skill when the work needs several steps or a supporting reference. In the lab, drafting a spec fits because the agent needs to turn a feature note into observable behavior and expose open decisions.

Create `.opencode/skills/spec-writer/SKILL.md`:

```md title=".opencode/skills/spec-writer/SKILL.md"
---
name: spec-writer
description: Draft a Task API feature spec with verifiable criteria and explicit open questions.
---

Read the feature request and the relevant route in src/app.ts.
Look at specs/registration-validation.md for the shape of a lab spec.

Return a draft with Goal, Acceptance criteria, Verification, and
Open questions. Give each criterion an input and observable outcome.
Cover the success path and what should happen to state on rejection.

Keep unresolved product choices in Open questions. Leave files unchanged
unless the caller asks you to save the draft.
```

OpenCode discovers project skills by path and makes the description visible to the model. It loads the instructions when the skill is selected. The skill ID here is `spec-writer`, taken from the directory.

## Test it with an underspecified request

Open a fresh Plan session and ask:

```text
Use @spec-writer to draft a spec for adding task labels. The caller
wants to find urgent tasks and remove labels they no longer need.
Surface the decisions that still need an answer.
```

Check the session activity for skill loading. Then review the open questions. The request leaves several decisions open: how to handle duplicate labels, whether case matters for filtering, and whether an empty list clears labels. Compare the draft with the agreed behavior in `specs/task-labels.md`.

If the agent invents requirements and presents them as settled, amend the skill with a concrete instruction about those choices. Try the prompt again in a fresh session. Use the same prompt with another model to see whether the description is enough for discovery and whether each model follows the procedure.

## Decide where the skill should live

Keep this one in the lab while its procedure depends on the lab's spec shape and paths. A team can share the same skill once the workflow is useful across projects. Review the instructions and any supporting scripts before adopting a skill from another repository. Its contents enter the agent's context and may influence what tools the agent asks to use.
