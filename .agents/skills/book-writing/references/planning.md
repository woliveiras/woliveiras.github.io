# Plan the book

## Define the reader promise and choose the main structure

Describe readers in terms of what they can already do. Identify the knowledge, tools, and materials they need at the outset and what the book will teach them to use. State the promise as an ability they can demonstrate in a realistic situation. Decide how readers can show they have reached that outcome, such as by solving a case, justifying a choice, or producing something they can check.

Base the structure on how readers will use the book.

| Primary use | Organize around | What each unit should deliver |
|---|---|---|
| Learn in sequence | Skills that build on one another and stages of the work | A result or understanding readers can use at the next stage |
| Look up answers | Recognizable questions, symptoms, or tasks | A clear starting point, a way to recover prerequisites, and an answer that is easy to find again |
| Make decisions | Constraints, alternatives, and consequences | Criteria that apply across cases, with limits and conditions for choosing an option |

In a book that serves more than one purpose, identify the main reading path and mark entry points for reference use. When readers jump into a chapter that depends on prior work, say what they need to have and how to check that it is usable. Put this check before the first decision and point to the material that helps readers get ready.

If several units answer the same kinds of questions, repeat the labels readers will look for and give each unit room to explain what is difficult about its subject. In long books, offer an overview of parts and chapters and a detailed table of contents when readers need to locate specific sections.

## Build a table of contents that shows dependencies

For each chapter, record **the reader's question**, **what they will learn to do**, **how they can verify the result**, and **what preparation they need**. Name the knowledge, decision, or artifact they need, where they get it, and where they will use it. Indicate whether the connection is a prerequisite, a brief refresher, or an extension. Mark chapters that can stand alone when they can supply their own prerequisites. If you introduce a concept early, teach the part that resolves the problem at hand and point to where it will be developed further.

A dependency is real when changing the order leaves an explanation, action, or interpretation without the foundation it needs. Check that each chapter makes a distinct contribution. Combine chapters that teach the same skill, move prerequisites to where readers can learn them in time, and name variants using the terms readers would look up. Use parts to signal a change in goal, scale, or stage of work. Open each part by explaining the condition its chapters share.

Use a recurring example when readers build on earlier artifacts or when keeping conditions fixed makes a difference visible. Track the state of the example at the beginning and end of each chapter. Choose independent cases to compare contexts, test whether readers can apply an idea elsewhere, or show where a rule reaches its limits. A short editorial record can track preferred terms, the state of the example, and cross-reference destinations.

If repeating a stage would be costly, say how readers can recover the state they need and tell whether it provides a usable starting point. If that state is hard to place in a long progression, bring back the roadmap at transitions and mark what is already available.

**Original example.** In a book on cataloging a teaching collection of ceramics, the first chapter shows readers how to assign each object a number and create its record. The second uses that number to link a photograph to the record so readers can identify the object from the image. The third uses the record and photograph together to spot switched labels when checking a shipment. A section on choosing a photo background can serve as a standalone reference if it states how the collection frames its photographs.

## Give each opening and the conclusion a job

Use the preface, when there is one, to explain how the project began, why its scope was chosen, or how to read the book. Use the introduction to make the problem, the promised outcome, and the path to it concrete. In a short book, one opening can serve both purposes. Use a chapter opening for that chapter's problem and immediate starting point.

In the conclusion, return to the situation that motivated the reader promise. Show what readers can now do, how to combine the skills the book taught, and when to consult specific sections. If the book ends with a case that brings several skills together, give readers criteria for checking their work.

## Design for reference use at the point of need

| Where it belongs | Editorial criterion |
|---|---|
| Main text | Define a term, state a condition, or teach a step where readers first need it to understand or act. Keep decision criteria where readers need to apply them. |
| Glossary | Give a standalone definition of a recurring term or one that is easy to confuse with another. Use the term adopted in the book, define it briefly, and add a distinction or a reference to an application when helpful. |
| Reference table | Collect values, options, or decisions that readers look up using the same questions. Give units, applicable conditions, meaningful row labels, and enough guidance to interpret the table. Place it next to the task when readers use it often. |
| Appendix | Set aside a self-contained resource that readers can consult or reuse as a whole, such as a blank form, a consolidated listing, an extended demonstration, or worked solutions. Keep instructions and conditions essential to the task in the chapter. |
| Index | Create entries for problems, terms, and alternative names that readers would look up. Point to substantive passages and add subentries when a term serves different purposes. Use stable headings and anchors until final pagination. |

In the main text, name the destination of each cross-reference and say what readers will find there and why it will help. Provide a way back when readers need to resume a procedure. Try finding a term, a rule, and an artifact starting from the questions readers would naturally ask.

If an exercise that brings several skills together requires decisions taught earlier, put those questions and the sections that support each decision next to the exercise.

For readers with different backgrounds, an appendix can teach an entire prerequisite skill that some need to catch up on. Give the appendix a clear starting point and a check that shows when readers are ready to return to the chapter. When solutions are separate from exercises, use matching identifiers and tell readers where to resume the exercise.

**Original example.** Define “accession number” on the first catalog record. Give the glossary a standalone entry. “Accession number. An identifier assigned to an object when it enters a collection and used to find its catalog record.” Put a blank copy of the record form in the appendix and name it in the passage that explains how to fill it out.
